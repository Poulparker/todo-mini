# МИП‑2. Воспроизводимый эксперимент p95

Группа МИП‑2. Замеры выполнены 27 ноября 2026 года на Windows 11 (AMD64, 12 логических процессоров), Python 3.12.14. Прогоны шли последовательно. Chrome оставался открыт. Питание, температуру и фоновую нагрузку во время замеров отдельно не фиксировали.

## План и гипотеза

Режим A заново вычисляет преобразование для каждого числа. Режим B переиспользует результат для одинаковых чисел внутри одного запроса. Каждый запрос запускается в новом процессе Python. Гипотеза перед замерами состояла в том, что p95 режима B будет ниже из-за меньшего числа повторных вычислений.

`duration_ms` — полное локальное время успешного запуска в миллисекундах, включая создание процесса, чтение данных, вычисление, вывод и завершение. Время измерено через `perf_counter_ns`. Порядок прогонов — A1 → B1 → B2 → A2. В каждом прогоне 20 измерений и 2 прогрева, `seed=2026`, 3000 строк, 24 итерации преобразования, тайм-аут 1000 мс, искусственная задержка выключена.

Для p95 сортируем `duration_ms` успешных попыток с `phase=measured` по возрастанию и берём значение с рангом `ceil(0,95 × N)`, считая с единицы. Прогрев исключаем. Доли ошибок и тайм-аутов считаем от всех измеряемых попыток.

## Отдельный контроль тайм-аута

Каждой из трёх попыток добавили 500 мс задержки при лимите ожидания 50 мс. Все три получили статус `timeout`. Успехов 0, ошибок 0, доля тайм-аутов 100%. Поле `duration_ms` пустое. В `observed_wait_ms` записано 84,5452, 66,8036 и 65,1209 мс. Время создания и завершения процесса увеличивает наблюдаемое ожидание сверх лимита. Анализатор выводит `null` для p95 успешных и всех попыток.

Подстановка нулей ошибочно показала бы мгновенное выполнение. Показ только успешных ответов без доли успеха скрыл бы все три тайм-аута. Контроль хранится в `output/timeout_control` отдельно от таблицы A/B.

## Воспроизведение

Команды выполняются из корня распакованного архива с Python 3.10+. В Windows при стандартной установке можно заменить `python` на `py -3`. `output` содержит сохранённые замеры. Повторные запуски ниже пишут в `output_recheck`. Для ещё одного повтора выберите новое имя каталога.

```text
python -m unittest discover -s tests -v
python measure.py --mode A --repeat 1 --out output_recheck/A1
python measure.py --mode B --repeat 1 --out output_recheck/B1
python measure.py --mode B --repeat 2 --out output_recheck/B2
python measure.py --mode A --repeat 2 --out output_recheck/A2
python summarize.py output_recheck/A1 output_recheck/B1 output_recheck/B2 output_recheck/A2
python measure.py --mode A --repeat 1 --count 3 --warmup 0 --rows 200 --rounds 2 --timeout-ms 50 --delay-every 1 --delay-ms 500 --out output_recheck/timeout_control
python summarize.py output_recheck/timeout_control
```

Во всех пяти каталогах `output` есть `raw.csv`, `run.json` и `input.json`. Итоги анализатора сохранены в `output/summary-ab.json` и `output/summary-timeout.json`. Все 5 тестов из комплекта прошли. ИИ использовался при оформлении отчёта. Числа и хэши отдельно проверены по файлам.
