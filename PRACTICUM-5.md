# Практикум 5. Автоматические тесты, исправление дефекта и Git revert

Репозиторий `Poulparker/todo-mini`, ветка `fix/tested-bug`. Исходный коммит с тестами — `22f5040604095d0b0414441d639770cbcbca6c8e`.

## Команда запуска

В корне репозитория с Node.js 18 или новее:

```bash
node --test --test-reporter=tap
```

Для запусков ниже использовался Node.js v24.22.3. Тесты на `node:test` вызывают функции из `tasks.js` через экспорт `TaskLogic`. Зависимости, браузер и хранилище для запуска не нужны. В выдержках из фактического вывода опущены подробности времени отдельных тестов и стек ошибки.

## Проверки

| Случай | Что проверяется |
| --- | --- |
| Основной | Фильтр «Активные» работает вместе с поиском «куп». Поиск учитывает нормализацию регистра и пробелов в запросе, счётчики отражают состояние задач. |
| Граничный | Текст из 200 символов принимается. При 201 символе возвращается ошибка ограничения длины. |
| Ошибочный | Строка из пробелов после очистки считается пустой. Задача, совпадающая с существующей после нормализации регистра и пробелов, отклоняется. |
| Подсветка | Совпавший фрагмент помечается, остальные символы сохраняются. Пустой запрос оставляет весь текст без подсветки. |
| Регрессия | Поиск «елку» находит «Купить ёлку», запрос «елк» выделяет исходное «ёлк», а добавление «Купить елку» определяется как повтор. |

## Дефект и воспроизведение

1. На коммите `22f5040` открыть `index.html` и добавить задачу «Купить ёлку».
2. Ввести в поле поиска «елку». Ожидается, что задача останется в списке и совпавший фрагмент подсветится. Исходная реализация скрывает задачу.
3. Очистить поиск и попробовать добавить «Купить елку». Для этой пары написаний проверка должна сообщать о повторе.
4. Запустить команду тестов. Пятый тест останавливается на первой проверке: поиск возвращает `false` вместо `true`.

### Исправление

Коммит `02d99ceeab04031be43f42dc7bc2ce87b1520439`. В `tasks.js` добавлено общее преобразование букв для сравнения. Оно приводит строку к нижнему регистру и заменяет «ё» на «е». Поиск и проверка повтора используют его после очистки пробелов. Подсветка ищет совпадение в преобразованном тексте и берёт фрагмент из исходной строки по тем же позициям, поэтому пользователь видит «ё».
